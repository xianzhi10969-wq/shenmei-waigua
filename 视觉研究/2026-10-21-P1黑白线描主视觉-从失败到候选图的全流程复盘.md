# P1 黑白线描主视觉｜从反复失败到可保留候选图的全流程复盘

> 整理日期：2026-10-21  
> 项目：审美外挂（Shenmei Waigua）  
> 范围：本轮“艺术首页首屏”探索；以当前对话与此前交接为依据，记录失败—纠偏—试验—用户反馈—阶段性成果。  
> **状态：视觉方向取得阶段性认可，整图为候选素材，非 P1 上线定稿；不能以本文授权覆盖现有主页、前端代码或 Figma 母版。**  
> 本文不等于所有独立 PNG 已入 GitHub / Figma。特别是本次无字整图在 Figma 的 **画框已建，原始 PNG 仍未导入成功**。

## 一、原本真正要解决的是什么

用户追求的不是“比以前好看一点”的网页，而是能让人第一眼获得 **aha moment** 的艺术世界：

- P1 首页以强烈的主视觉和标题建立气氛，不再让四个问题占据第一屏。四个问题不是删除，而是保留在痛点/问题地图等后续体验中。
- 参考 [Emergence](https://emergenceprojects.com/)、尤其是 [/6/](https://emergenceprojects.com/6/) 与 [/7/](https://emergenceprojects.com/7/)：学习**不同材料与线描层级的关系、整体艺术语言、留白与密度对比、网页展陈感**，不是复制其物件、花纹、具体构图。
- P1 只用黑、白、钢笔线描进行第一阶段绘画，暂不依赖色彩、CSS 装饰线或前端“假绘画”；先做图像，后做网站。
- 横向桌面首屏要留出真实的标题位置；手机端必须重新构图，不能直接把宽画幅缩小或裁掉人物。
- 气质为来自“未知文明”的、非特定宗教的仪式性陈列/神龛世界；不画可以辨认具体教派的圣像符号。
- 只保留**单侧人物**，理想状态是不强调年龄和性别；人物身份是安静的见证者/守龛者，手势与中心物件发生关系，而不是两个人左右对称充当装饰。

这些要求之间有明显的优先级：**构图与世界观 → 单件绘画质量 → 层级与组合 → 标题、网页和交互**。过去多次把优先级倒过来，造成反复“80 分但不惊艳”。

## 二、过程时间线：每个转折究竟改变了什么

### 01｜从“做 PPT”转向真正的美术指导

最早的迭代经常表现为：固定文字区和图片区、修改边框、调字体、增加装饰、局部加强纹理。布局可用，但元素之间没有内在关系。用户多次评价“没有 Aha moment”“像 PPT”“太普通、太平均”。

关键纠偏：不先问某个装饰放哪儿，而是先问 **这一屏呈现什么完整场景／世界**。当首页被设定为“标题＋一幅强视觉主图”，图像主体、构图留白、观看方向才有共同的命题。页面不是海报的散件拼贴。

### 02｜研究 Emergence / OSP / 历史钢笔插画，但不能照搬

参考研究不断收敛：用户欣赏 Emergence 的强烈图像、不同区域的线条复杂度，以及材料感“从内到外”决定整个网页的方式。艺术家方向收束至 Aubrey Beardsley、Harry Clarke，并借鉴 Robert Fludd 那类宇宙图解的秩序与仪式空间组织。

其中一次重要警告：生成图里出现的**八角星、垂挂珠链、几何边框、中心碗状祭坛**，与参考站太像，用户亲自截图指出。由此明确：

- 可学习的是 **视觉语法与方法**（背景重复、人物主次、黑白块、图像结构）。
- 不能照搬的是 **物件的轮廓、星星形状、图案、祭坛器皿和排布**。
- 对标图不是待拆分的素材包；原创性要落实到“换物种”，而非改一点细节。

### 03｜先用纯黑白线稿寻找神龛世界，而不是直接做完整页面

先确定“非特定宗教的神龛／陈列空间”，通过黑白线稿研究中心性、拱形结构与仪式感，不加文字。第一轮画幅偏独立插画，无法直接适配宽版和手机，且缺少标题安全区与人物。

接着提出横向构图：**左侧大片安静留白，右侧偏心的主物件和单个人物**。不必强求对称。人物承担观看指引：面向中心或伸手触及中心物件。

### 04｜跨文化人物研究转化成造型约束

研究中国白描、宗教版画、欧洲圣徒造型等“神圣人物如何以线条被画出来”。启发是**姿态、衣褶、轮廓和与空间的关系**，不是堆砌面孔与宗教道具。执行时要求：

- 不强调性别/年龄；削弱肖像化五官，避免明显男性/女性服饰程式。
- 身体由长袍轮廓支配，不通过胸腰臀建模。
- 人物必须有明确重心、头部方向、伸手动作；手势指向主物。
- 尤其保留早期受到肯定的 **深色袍子厚重的黑白关系**，不能因“统一画风”把深度擦掉。

注意：以上是目标标准，不等于后续生成候选图已完全满足；最终人物面貌的去性别化仍需继续校准。

### 05｜剔除错误“物种”，统一为一个室内世界

一版场景里混入草木、石头、户外地坪及风景性遗迹。用户明确指出这些元素不属于该世界。调整后的世界定义为：

**一处来自未知文明图录的神龛内室／仪式陈列空间。**

由此禁止任意写实植物、山石、户外风景、荒野废墟。结构、基座、织物、物件应共享同一套材料与造型语言。地面只承担必要的空间承托，不应凭空长出写实石板、过量瓷砖花纹或复杂景观。自然元素如果存在，也必须经过明确的图案化设计，不能成为随手填空的风景。

### 06｜密度失败：统一画风 ≠ 处处画得一样多

几次成图的真正问题是：背景、拱门、祭坛、地板、人物袍子都精细，且线条频率相近。整体因此失去远近、呼吸与视觉焦点。

用户特别认可 Emergence 里**不同部分拥有不同复杂度**：背景是单调而有秩序的重复花纹，其间少量星星/点缀，人物则可以具有远高于背景的描绘深度。

逐渐形成清晰的密度阶梯：

| 层次 | 工作职责 | “简单／复杂”的真正含义 |
| --- | --- | --- |
| 左侧标题预留区 | 让主体有呼吸，也服务文字 | 几乎不画；不是把密集纹样调成浅灰 |
| 背景秩序 | 提供“世界的空气” | **少种类、重复、间距均匀、简单清晰、没有自成故事的小景观** |
| 神龛与建筑 | 提供秩序和空间承托 | 中密度，突出轮廓与空间关系，不让每块表面都布满雕饰 |
| 中心器物 | 视觉记忆点与语义焦点 | 轮廓鲜明，适当集中笔触；不能像别人的祭坛 |
| 单侧人物 | 最大的明暗重量与细节深度 | 深袍可有大片黑色；衣褶有疏密变化；只有局部精细刺绣 |
| 少量点缀 | 让层级之间产生节奏 | 有明确原因才出现，严禁随机装饰和重复挪用参考网站元素 |

**“背景简单”不是模糊、透明、草率或没有绘画感，而是结构简明、词汇少、重复有规律、复杂度低于主体。**  
**“绘画感”不是每厘米平均做旧，而是看得见每一笔的选择、起止、曲率与停顿。**

### 07｜误入 SVG / CSS / 算法排线，确认为失败支线

为了精准控制笔触，曾广泛找 GitHub 的 Inkscape、Krita、排线、Bezier 路径、Perfect Freehand 等工具，也尝试程序化 SVG 人物、局部路径绘制和“人物线描试样”。

这部分的核心错误是：**把“可计算的线条精度”当成“绘画艺术质量”**。结果人物像技术示意或卡通符号；另一些直接生图又变成素描式灰阶、糊成一片的交叉排线、奇幻时装式满身刺绣。用户明确要求“偏线描，不要偏素描”，并反对拿 SVG/CSS 代替真正的绘画素材。

留下的方法价值仅限：后期工程如何分层/导出/管理、以及某些专用修线可行性。**本轮这些工具不等于已经被用于绘制获认可的人物。SVG 程序人物与素描化支线不应继续作为美术母版。**

### 08｜真正有效的关键转折：先抠人物，再从已通过素材编辑

生成模型连续几次在要求“只画一人”时依旧给出整幅神龛景观，背景和人物被一起重绘，导致每一轮都可能丢掉已认可的袍子深度与手势。

用户提出最具执行价值的纠偏：

> 先把东西抠出来，再以抠出来的为基底去改。

因此不再把人物、神龛、背景捆绑生成，而是先将人物作为独立透明背景素材提取与调整。用户给予“好多了，可以暂时先用这个版本”的反馈。这一步把人物从一张不可控整图，变成 **可重复使用、不必每轮重造的独立视觉基准**。

注意：**人物切出是实际发生的阶段性进展；不能因此宣称最后一张整体图已经在 Figma 中以全套原生独立层逐件合成。**

### 09｜重新组装一度又复制参考，再次发现问题

人物确定后，又试过生成完整宽版。画面一度把 Emergence 的悬挂珠链、星形、几何纹和祭坛直接借入。用户指出“照搬不好，而且说好了一层一层来”。

随后的改法不是推翻整个 background。用户表示 **目前 background 的线稿密度很好，保持一样**；需要更换的是中心祭坛及其形状。即：

- 好的部分 **锁定，不动**；
- 不对的部分 **仅在对应图层/物件上改**；
- 不拿“统一风格”的理由重画人物和背景；
- 引用他作的相同符号形态，应换成原创且与项目语义有关的物件。

### 10｜换中心符号的“物种”：P1 圣匣、P2 黑镜、P3 感知灯器

曾单独生成三个中心符号方向（独立素材而非一张混合看板）：

- **P1：圣匣／陈列匣。** 含“收藏、命名、封存感受”的语义，外形与参考祭坛碗不同。用户表示喜欢。
- **P2：黑镜／圣镜。** 有“观看、反观”的概念，但本轮未被列为优先候选。
- **P3：感知灯器／仪式观测器。** 保留神灯的神秘记忆点，但不再使用被指出相似的碗状祭坛轮廓。用户也表示喜欢。

阶段性方案为 P1 做主中心，P3 作为可保留的备选或辅助语汇；**不能擅自假设 P1/P3 都已被正式确定为品牌永久符号**。应继续检查小尺度可辨识、与人物手势的关系及是否落入熟悉的真实宗教造型。

### 11｜最新无字宽图：可以保留的候选版本，而不是流程终点

在上述讨论后产出一张 **1672 × 941 PNG**，文件名为 **《哥特式圣殿中的静谧礼拜.png》**。画面具有：

- 左侧可以放标题的大面积留白。
- 右侧单名披袍人物，人物及衣袍的黑白重量强于背景。
- 偏右的拱形陈列空间、中心物件与前景的小型仪式物件。
- 黑白线描气质，按区域分配了不同视觉复杂度。

这张图获得继续保存和复盘的意向，但**尚不能推断已逐层原样采用 P1/P3 各 PNG，也不是已通过手机端/视觉原创性检查的终稿**。尤其应复查：过于哥特化的建筑结构、人物是否仍过于女性化、地板结构与悬挂符号是否又接近旧对标。

**技术事实：最终交付是一张合成的无字 PNG；它不是 Figma 里已经独立可编辑的“背景/人物/神龛/器物”多图层文件。** 已学会分元素锁定和以原图作基底，但今后必须在真实工程里把“分层”落实为独立资产文件与 Figma 节点，不能只停留在 prompt 的逻辑分层。

## 三、这次到底做对了什么：不是神奇 prompt，而是减少了不确定性

1. **设计命题先行。** 从“加一个装饰”改成“未知文明的仪式陈列世界”，草木石头等不合题的元素被自然排除。
2. **先构思横幅并留白。** 左侧标题空间、右侧主体、单人偏心重心事先约束，画幅开始像首页而非封面插画。
3. **从平均精致转为有选择的细致。** 背景简单重复，结构适中，人物袍子有真正的细节聚焦。
4. **保留成功对象。** 早先人物袍子深度、仪式灯记忆点、后来认可的背景线稿密度，不再因修改其他对象而消失。
5. **用“抠图／原图编辑”替代反复重造。** 每多保留一件独立素材，下一轮就少一个随机变量。
6. **把原创性变成硬性验收项。** 用户指出照搬后，改变的是符号“物种”，而不只是给原祭坛换纹理。
7. **将工具回归适当位置。** GitHub 工具用于调查画法、独立图层、修线与后期技术；不会因为装了某工具就自动获得艺术指导能力。
8. **把认可边界写清楚。** 用户的“好多了”“暂时先用”“P1/P3 喜欢”“行”对应阶段性认可，不得升级成整站上线许可。

## 四、今后的标准制作工序（必须按顺序执行）

**第一阶段｜确认创作命题与画面规则**
1. 写明本屏的心理任务、世界观、一句话场景、不能出现的元素。
2. 找参考图，并逐个标明“学习的是构图／材料／笔触／功能”，设置 **不得描摹的图形清单**。
3. 画构图研究稿：桌面宽幅与手机竖幅同时考虑，先留标题安全区；构图不通过，不开绘制细节。

**第二阶段｜逐件制作独立艺术素材**
4. 列出素材资产表：背景、拱门/陈列体、中心物、单侧人物、少量点缀。标出各自的造型来源、线稿复杂度与前后遮挡关系。
5. 每次只制作**一个独立物件 PNG**；如果已有较好的物件，优先抠图及在该基底上局部编辑，不从零生成一张新整图。
6. 每件素材都独立验收轮廓、线描而非素描、色阶、密度、背景透明、原始尺寸以及和相邻物件的世界观一致性；不通过则回退，不带问题进入拼合。

**第三阶段｜组合与质量检验**
7. 把每张独立的素材依次放入 Figma 的独立节点（或临时专业绘图文件的真实图层），只通过位置、缩放、遮挡来组合；**制作节奏逐件，用户验收可以按整轮汇总**。
8. 显隐各层检查视觉主次：背景是否又太响、人物衣褶是否失去深度、中心物是否反客为主、标题区是否真实可用。
9. 核对原创性：把新稿与 /6、/7 的具体器物截图并排；若形状、纹样与构图明显相同，重新设计对应物件，不许继续描摹。
10. 通过后再叠标题、网页动效和响应式实现。网页 CSS 可以负责布局和真实交互，但不应凭空用 CSS 假线条替代已验收的美术插画。

**版本控制规则（强制）**：每次实验都另存独立版本，不覆盖当前已确认的 P1/P2 或 P3/P4。用户明确说“保留”的角色、背景密度、交互、字体必须作为下一轮输入锁定。任何批准都只针对被评审的维度，不自动批准整页重构。

### B. GitHub 检索过的工具（**研究过 ≠ 应用到最终主图**）

- [Krita](https://github.com/KDE/krita)、[Inkscape](https://github.com/inkscape/inkscape)：专业绘画/修线与独立素材工作流。
- [HatchFill2](https://github.com/dapperfu/inkscape_HatchFill2)、[Line Shading](https://github.com/Luca-Lauro/inkscape-line-shading)：局部排线的研究；**不得用来机械铺满人物或整图**。
- [Coherent Line Drawing](https://github.com/SSARCandy/Coherent-Line-Drawing)、[linedraw](https://github.com/LingDong-/linedraw)：图像转线稿底稿可能性；不是艺术完成度保证。
- [Paper.js](https://github.com/paperjs/paper.js)、[vsketch](https://github.com/abey79/vsketch)、[vpype](https://github.com/abey79/vpype)：可重复几何、绘图路径与后期清理研究，**不得拿几何代码“冒充”钢笔插画**。
- [Mannequin.js](https://github.com/boytchev/mannequin.js)、[Composition Grid](https://github.com/rrmn/composition-grid)：人物姿态与画面重心的构思辅助。
- [Islamic Patterns](https://github.com/evoluteur/islamic-patterns)：学习一套纹样如何来自共同结构规则，**不能直接移植某个宗教装饰**。
- [Perfect Freehand](https://github.com/steveruizok/perfect-freehand)、[svgpathtools](https://github.com/mathandy/svgpathtools)：曾探索笔锋与路径控制，但本轮出现了 **机械 SVG 人物失败稿**；不可误记为“最终精品采用该插件制作”。

这些条目属于“方法检索记录”，不是二进制素材的许可证声明，也不是已安装/已实际使用证明。

## 七、仍未解决的质量门槛与明确的下一步

1. **画风精度**：真实钢笔线描仍有差距，减少素描灰阶、机械对称与全身同频细纹；对人物手、脸、衣褶分别做局部笔触校验。
2. **原创性**：候选宽图仍需复查哥特尖拱、装饰纹、悬挂饰与参考站是否过于相近；一旦相似，替换**对应物件**而非重画已认可的背景／人物。
3. **去性别/年龄**：人物最终造型未完成该项专项验收。
4. **分层真实性**：应拿回真实独立透明 PNG 建立 Figma 图层；最终整图 PNG 不能倒过来充作“独立图层已完成”。
5. **移动端**：当前 1672×941 候选图不能视为手机版本；手机须另作竖向构图，并保留相同世界和层级。
6. **标题字体与网页**：P1 title 仍是临时效果，勿把默认字体直接覆到图上；交互、P2 四问题、P3/P4 现有基线保持不动。
7. **同步状态**：Figma 的原 PNG 上传待完成；GitHub 当前只写下复盘，不把“文档已同步”误说成“所有图像已同步”。

## 八、给下一位协作模型／Codex 的一句话

> **先把艺术作品画对，再组装成网页。已认可的东西锁住；每一轮只改变有问题的那个元素。背景应简单重复，人物可深重精细；抠图/原图编辑优先于重新生成整场景。模仿参考的视觉组织方式，严禁照搬具体器物或花纹。完成素材需逐件独立保存，Figma 要核验真实图像上传；未验收不覆盖线上及当前预览。**
