# 审美外挂：数据与页面协作约定

- 飞书 Base 是内容真源，站点是 `lark-cli` 同步生成的静态快照。所有题目、意象、提示语、状态和排序先写入 Base，再运行 `python3 scripts/sync_from_lark.py`。不要把新题硬编码到前端。
- 所有 `lark-cli` 调用显式使用 `--profile aesthetic-feishu --as user`。表 ID、字段及类型由 `data/contract.json` 固定；若飞书字段发生有意迁移，同一次改动必须更新契约、同步脚本、转换脚本和前端，并跑完整同步。
- `scripts/check_contract.py` 是构建门禁。字段缺失、类型变化、题库不完整、重复命题或提示不是开放式问题时，停止构建与发布。
- 前端不宣称已保存或上传用户创作；目前没有相应后端。自己出题仅存在于当前页面。
- 词条页按独立字段组装：`钩子` 和 `核心` 作开场，案例读案例表并按 `是否保留` 过滤，做法读 `做法1–3`。词条表的 `正文` 是包含这些内容的旧长文汇编，不得整篇映射到页面或公开快照，避免重复和过期案例重新出现。不要因前端不展示而删除 Base 原记录。
- 迭代阶段只在本地修改、构建和预览，不自动发布 Sites 或 Netlify。每轮向用户展示本地结果；等用户明确表示这一版可以上线，再统一发布。不要把本地预览说成线上已更新。
- 上线前从飞书重新同步并通过 `scripts/check_contract.py`；核对 `dist/data.json` 的生成时间、记录数与页面，测试桌面和手机宽度下的核心路径。
- Netlify 大陆访问镜像 `https://subtle-peony-38e354.netlify.app/` 与 Sites 主站必须使用同一次 `dist/` 构建产物。确认上线后将同一产物发布到两个入口；发布后至少核对 `index.html`、`app.js`、`data.json` 和图片响应。若任一入口尚未更新，不要宣称双站已经同步。

## 跨会话协作与收尾（减轻用户管理成本）

- 新会话先确认**实际工作目录、Git 分支、未提交修改**。读取本目录的 `README.md` 和与任务相关的 `docs/` 文档；从现有文件、代码和 Git 历史恢复上下文，**不要求用户重复描述旧对话**。GitHub 远程备份不能证明本地当前状态。
- 继续一个已有项目时，默认复用其工作目录。**新聊天不等于新项目**，不要因新对话自行复制工程、另建工作目录或改变部署目标。
- 用户表示「研究、想想、先看方案」时属于探索，先只读调查并给方案，明确批准前不修改。对数据库批量写入、删除、迁移结构、覆盖已验收版本、合并分支、线上发布，也必须明确确认影响范围并获得批准。
- 每次任务结束，用简短中文说明四件事：**实际改了什么、如何验证、哪些尚未完成、是否已保存到本地/GitHub/线上**。这些状态不得混为一谈。
- 当有新的**已核实且被用户接受的里程碑**时，更新 README 顶部的「当前状态与新会话入口」，确保后续 Codex 能接手。不要把计划写成完成，也不要覆盖历史交接或在未明确授权时自行发布。
