## 本版已经确定的产品决策

词条应是**连续阅读的单页**，不再为每个作品建立独立案例详情页。点击图像展开图廊，关闭后应回到该词条和原阅读位置。**手机端是第一优先级**，桌面布局根据同一数据响应式调整，不单独创造一套内容。

正常阅读路径为：封面 → 词条引导（案例之前）→ MASTERS 的可变案例列表（逐案例含图／原文、完整分析、官方跳转）→ Pinterest 搜索词与可选配色 → 末尾导航。暂不制作 FOR YOU 创作方法板块。

## Feishu 数据和渲染契约

飞书 Base 通过原有 CLI / `sync_from_lark.py` 同步，网站实际读取 `dist/data.json`。**飞书是内容真相源**。本设计使用的是 2026-10-14 GitHub 备份快照，正式编码前应核验最新同步记录，不可据此声称已经写回飞书。

词条字段：`term.name`、`english`、`hook`（作品之前的解释）、`core`（核心观点）、`searchTerms`（待策展 Pinterest 用词）、`colors`（仅有可靠 HEX 时显示）。案例字段按 `termName` 关联，筛选 `keep` 并按 `order` 排列；案例数量没有固定上限。每个案例至少保留 `name`、`author`、`year`、`medium`、`why`、`whyLong`、`official`、`images[]`，有值时再渲染 `scene`、`detail`、`method`、`twist`、`absence`、`extra` 等辅助分析。

**每一条 `case.official` 都必须渲染为真实、可点击、外跳的官方来源链接**，不可隐藏在纯文本里。无图片但有文字的案例不能被过滤掉。

## 自适应图片展示规则（策展式默认布局）

- **0 张**：文字/诗歌/音乐/资料等非视觉媒介版式，不出现空白图片框。
- **1 张**：尊重原图比例，完整展示一张。
- **2 张**：展示两张，可主次纵向或并排。
- **3 张**：一大两小，三张都可以看见。
- **4 张及以上**：一张主图 + 第二张 + 第三格作为“+剩余数量”入口（这里仅两张实图完全可见，遮盖格显示 `+(N-2)`）。点击进**该案例自己的完整图廊**，索引应包含所有 N 张并保留后台排序；不要把所有 N 张直接插入正文撑长页面。
- 主图可直接点开大图；图廊可点缩略图进入大图。网页正式实现时支持左右滑动、触屏缩放、关闭恢复滚动位置。
- 不得裁坏杂志封面文字、艺术作品重要部分；必要时 `object-fit: contain`，允许以后增加“主图/图片显示策略”策展字段，不为所有词条写死同一裁剪。

> 原 Figma 十图实验的 `+8` 是人为构造的边界案例。Snow 当前快照只有三张，Hokkaido 两张，**不允许把演示数量误当成真实数据**。

## 配色与灵感入口

配色默认是**词条级、可选**内容，**不要求每件作品自动取色**。仅在来源可靠、HEX 有效时呈现色板；当前很多 `colors` 为“待取色”，不准显示捏造的色板。Pinterest 搜索词也是策展内容，现有 `searchTerms` 是原始关键词，不等于都已适配 Pinterest。
