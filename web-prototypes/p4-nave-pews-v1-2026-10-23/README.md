## 打开与操作

```bash
cd web-prototypes/p4-nave-pews-v1-2026-10-23
python3 -m http.server 8765
# 访问 http://localhost:8765/
```

- 默认起点 P3 v3 原有窗图（`../p3-stained-glass-v3-2026-10-23/assets/window-web.png`；当仅解压这个实验目录时以文字占位替代，不生成新的彩窗）。
- 点击「沿着中央通道继续」：镜头推近当前窗后切到 P4 中殿整体构图，长凳进入可点击状态。点击「回到 P3 彩窗」返回。
- 桌面用 1200 × 880 黑线 SVG，手机用独立 390 × 780 黑线 SVG。一个半排长凳单元 = 一个细分审美词条；两侧左右配对，靠近通道的弯曲座椅端板和扶手形成实体感，不是电商格子。
- 点击/键盘 Enter/Space 选一张长凳；选中栏加深（仅黑与米白）。切换右侧专题选择器可换整馆专题，24 个值来自 P3 v3 的章节顺序。`?topic=eros` 可让 P3 传入当前专题；`?inside=1` 可直接从中殿预览开始。
- 暂时示意 8 个座位（4 排 × 左右各一），**不是飞书真实词条数**；每个座椅编号是结构索引而不是真实词条名。若某专题有超过 8 条，自动翻下一组长凳（真实只读数据接入后生效）。

## 研究依据：真实先例，不编造

1. **中殿的轴线与座位**。St Mary's Church Gosforth 早期照片，Sankey Photography Archive，记载「nave → altar」「pews on each side of central aisle」。[原始照片和描述](https://www.sankeyphotoarchive.uk/collection/view/?id=3162)。启示：长凳重复的纵深和中央通道必须优先于复杂花纹。
2. **长凳与拱廊的关系**。Historic England 的教堂中殿照片说明（1900–1939），有尖拱、pew ends 装饰与座椅排列。[Historic England AA108559](https://historicengland.org.uk/images-books/photos/item/AA108559)。启示：画端板和扶手有助于区分教堂长凳与纯矩形内容卡。
3. **展厅进入和作品信息的分层**。Getty 与 Google Arts & Culture 的 Pocket Gallery 说明了进入虚拟空间后逐间探索、再接近单件作品读信息的行为。[Getty 的案例](https://www.getty.edu/news/use-augmented-reality-to-explore-a-virtual-museum-gallery-from-home/)。启示：空间选择与文字详情分两层，不让图录填满画面。
4. **从入口选择站点并看展品**。Australian Museum 线上虚拟展览用空间行进点和作品标识实现导航。[官方操作说明](https://australian.museum/exhibition/virtual-exhibition-tours/)。启示：点长凳是位置选择，不必每张长凳平铺巨大的图片与标题。

以上只参考空间组织、视线与交互方式；没有复制任何参照图像到绘图资产中。

## 产品信息架构与字段映射

| 空间对象 | 数据源 | 映射/状态 |
| --- | --- | --- |
| 远处彩窗 | 飞书「章节」/ P3 v3 已有缓存 | 当前选中专题的 `record_id` / `序号` / `章节名` / `英文名`；**P3 图不重画** |
| 整座中殿 | 章节（24） | `topic.id` / `章节名`；在 P4 的 select 一次切换当前专题 |
| 一条半排长凳 | 飞书「词条」（101 条全表） | `所属章节` 关联当前专题；按 `章内序号` 排，`record_id` 作为 seat key，`词条名`/实际字段经 read-only 适配后显示 |
| 座椅画心（**本轮不画**） | 词条 `封面图` 附件只读缓存 | 将来作为局部插画内容；不得给整座教堂填彩色 |
| 选中态 | 前端临时状态 | `selectedTermId`；一张长凳黑色靠背，侧栏显示真实名称/简述 |
| V3 详情入口 | 真实词条详情路由（**未核实**） | 取得真实 V3 URL 才启用按钮；目前禁用，绝不编造路由 |

**真实字段安全线**：`词条名` 是本次拟议的前端规范化键，不声称飞书的原字段名已经核实；实施时需读取飞书实际字段列表再映射。当前因无可用的 101 条原始记录，只从 GitHub 中已同步的 P3 v3 缓存提取 24 个章节的真实名称。页面的 8 个「词条位置」都是明确写出的占位，**不属于真实数据集**。

若未来补齐 read-only 快照，在 `index.html` 初始化脚本之前注入 `window.P4_TERMS_BY_TOPIC = { 'melancholy': [{id:'realRecordId', chapter_id:'melancholy', title:'真实标题', summary:'...', v3_url:'https://...'}] }`，前端会自动按专题与席位分页；不向飞书写任何数据。注意真实实现应用 JSON 加载器，而不是手输内容。

## P3→P4 分镜假设

- **分镜 A / P3 彩窗**：观众刚在一级专题彩窗停留，专题 `topic` 持续保留。
- **分镜 B / 门槛**：镜头靠近 P3 图像并切换焦距；不增加 P1→P2 转场，不改动 P2→P3 接缝。
- **分镜 C / 中殿**：镜头拉开，远端仍留有「P3 当前专题」的窗轮廓，中央通道把视线引向远端，横排长凳从两侧出现。第一次显示四排左右各一张。
- **分镜 D / 细分词条**：选长凳 → 只切换该长凳的黑白选中态 → 右侧信息页显示内容 → 之后接真实 V3 链接。
- **反向**：退回 P3 时当前专题仍在，下一次进来默认当前章节图录。

## 结构约束 / 这一轮只动什么

- 两色：`#F6F3ED` / `#1E1E1E`。不使用渐变、阴影、噪点、金色、灰排线。
- 仅画结构和透视，不使用图片生成模型，不创造图章/宗教装饰美术；窗仅留简化位置标记。
- 绘图图层：背景、拱顶/立柱、窗位轮廓、地坪通道、长凳、选中态。供后续逐层审核。
- 输出：`pews-desktop.svg`, `pews-mobile.svg`（可编辑结构矢量）、`index.html`（可点）；`make_svg.py` 只用于确定轮廓数学关系。`*.png` 为本地预览截图，不是最终美术。

## 已知问题（待夕里审）

1. **镜头的空间语义尚需验收**：从 P3 窗向内进入，P4 看见同一窗处于远端，是「近景 → 拉出全景」的电影空间手法，并不声称建筑剖面严格连续。可继续只改镜头，不改座椅。
2. 结构图目前每侧一张半排长凳映射一个词条。现实一条 pew 可坐多人，这是有意的「内容单元 ↔ 家具实体」映射；如果强调「每一个人的座位」而非「一条长凳」，需另做一轮分座结构实验。
3. 实际每章节词条数与顺序未从飞书词条表验真；8 个是容纳能力演示，绝不当作真实数量。
4. P4 词条封面图、名称、摘要和真实 V3 深链未接；需飞书只读字段核实与路由确认。
5. 手机版只保留中央视线及四对长凳，未做屏幕阅读器全量路径/真机滑动审查。
6. P3 图像引用需在仓库目录结构下访问；解压单独目录会出现明确替代文字。
7. 不承诺与正式 v9 书册转场等价；它是互不覆盖的独立方向。
