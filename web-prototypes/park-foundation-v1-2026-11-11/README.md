## 推荐试用顺序

1. 入园 → 大道 → 浏览区 → 搜索“Dreamcore” → 进入“梦核”。
2. 点击右侧进度圆点到一个案例，点作品看原图，再关闭。
3. 到出站处收票 → 票根本 → 再坐一次，检查票根不会变成两张。
4. 回大道 → 街机厅 → 意象实验室 → 抽题 → 在空白屏幕写自己的联想 → 保存。
5. 票根本选择“我留下的”，检查内容、复制和备份入口。

## 编辑器与网页如何接上

编辑器点画布空白处，右栏通过 **放到网页的哪个位置** 选择中文用途。下表 ID 供协作查阅，不需要手动输入。放入素材并保存，网站约每 2.5 秒读到最新保存结果。两端分别读取 `mobile`／`desktop` 布局；文字、图片位置和图层顺序来自编辑器原数据，不另写一套坐标。

| 素材位 ID | 用途 |
| --- | --- |
| `p1-scene` | 首页整幅场景艺术层（入园按钮为独立 HTML） |
| `p3-browse` | 大道浏览区入口 |
| `p3-feelings` | 大道地图亭入口 |
| `p3-arcade` | 大道街机厅入口 |
| `p4a-balloons` | 气球摊艺术层 |
| `p4a-gacha` | 扭蛋机艺术层 |
| `chapter-gate` | 共用专题牌楼艺术层 |
| `p4b-interior` | 地图亭内景艺术层 |

本目录的 `editor-starter.json` 可在编辑器“导入项目”中追加这些空白场景。它不会替换现有场景；如果素材位冲突，导入场景的重复绑定会清空。空白布局不会覆盖网页占位。

当前桥接是**静态艺术布局**：按钮、内容、跳转仍由功能层负责；没有把编辑器内任意图片自动变成点击入口，也没有做完逐元素动效绑定。首页三层视差与正式分层资产的对应，后续接美术时再绑定。素材页需启动本目录 `serve.py` 才能访问共用艺术层，单纯静态托管前需要打包艺术数据；本轮未部署。11 月 12 日新增静态导出，见下文。

## 数据诚实边界

- 本轮读取的是已有 **2026-11-07 飞书只读快照**，不是 11 月 11 日实时同步。来源文件 SHA256、版本号、数量见 `data/provenance.json`。
- 24 专题、101 词条、144 案例、403 个被这些数据引用的原媒体文件、70 意象命题、9 问题、60 资源已独立保存。403 是本轮被引用并复制的文件数，不声称覆盖原工程全部 407 份原图。
- 现有快照内 55 个词条标记已上线、46 个待开放；这只是源数据状态，不代表 V2 文案或视觉已全部通过。
- 旧 40 个形容词入口和旧感觉路线不导入新版。`data/experience.json` 留出 `feelings`、`termFeelingIds`、`termStatements`，不手写假的推荐关系。
- 用户已明确：配色明天再谈；第一人称句尚未整理，先留数据入口。
- P5 的“三种布景”定义和飞书新表清单在原分镜里是空表。本轮只做已有证据的文字／作品布景与可变序列；不编造对照内容。
- 阅读不自动等于“认领”。没有句子时只保存乘坐记录；从已选感觉线路进入或明确点击“这句话像我”后，才记录认领。
- 票根存在当前浏览器 Profile 的 localStorage。编辑器的布局是本机服务共用；这两者不同。票根导出／导入可迁移 Profile，目前没有云端账户同步。
- 同一 Profile 的普通先后操作每次读最新存档，其他窗口存储事件会刷新展示；不是数据库事务，不保证两窗口完全同时写入时的强一致性。
