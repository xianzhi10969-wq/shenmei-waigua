## 怎么运行

在完整仓库根目录运行 `python -m http.server 8765 --bind 127.0.0.1`，打开
`http://127.0.0.1:8765/web-prototypes/p2-p3-junction-v1-2026-10-23/`。

- 默认入口从 P2 原画继续，只检查本次接缝；下滑进入完整彩窗，上滑按滚动位置反向计算星轨。
- `index.html?lineonly=1` 单独检查结构线，不播放接缝。
- `index.html?chain=1` 是桌面 v4 原始 iframe 的外接试验。它引用原目录，不复制、不改写 v4；原始 iframe 先完成自己的滚动区间，之后才交接星星。**完整画面尚未在本环境核验**，请勿因此称为整站贯通完成。
- `review.html?device=desktop&at=0.5` / `review.html?device=mobile&at=1` 分别以 1440×900 / 390×844 内嵌视口复核。`at` 只定位自然滚动位置，不替换运行中的动效状态。默认先看爱欲，左右按钮、键盘左右键、横向滑动均每次一格。
- [原始 v4 对照](../p1-p2-reveal-star-v4-2026-10-21/index.html)；[v3 内容系统](../p3-stained-glass-v3-2026-10-23/README.md)。

## 按变量拆开的改动

1. 接缝素材只画水波。使用图像生成工具参照 P2 下方水纹制作独立位图，经 Canvas 严格映射并导出成 `#1E1E1E`、`#F6F3ED` 两种专色；不把纹理、灰场或随机排线带进页面。不向 P1→P2 插任何新过渡。
2. 结构线是建筑骨架 SVG，重新拟合尖拱、玫瑰窗、四叶饰和柱头柱础，没有将小线稿放大，没有生成铜版装饰层。星星沿用 v3 的既有星 B 两色 SVG。结构稿与美术定稿是不同状态。
3. 24 个专题清单与封面直接引用 v3 的只读快照，封面原文件不改，继续 `object-fit:cover; object-position:center 30%`。修正了旧分区把四叶饰算入 glass 的开口范围，因此封面可见区域与 v3 截图有差别，需要一起审。标题、卷轴位置只作结构验证，未批准。

## 已知问题与未完成项

- **“同一根水线变成窗台”的运动关系尚未成立。** 本版实现了水波散入纸色、星星进入玫瑰窗；曾试验的悬浮连接线横穿拱顶，已从提案中移除。不能写成这一项已完成。
- P2 原画的底色本来是 `#14191E`，且原图底边有一条细线；它与新结构使用的 `#1E1E1E` 仍有轻微分界。保留 P2 原画，没有为隐藏这个问题去改 v4。接缝密度、线端节奏也仍需人工审图。
- 结构稿比夕里底层简化了部分拱肩连接和三叶窗头，尚未达到“逐线忠于底层”的程度。完整拱顶和玫瑰窗可见不等于结构美术通过。
- 本地 GitHub 连接的内容接口对超过 1 MB 的原始位图返回空内容，另外的二进制读取接口报解码错误。因此没有获得 v4 的 bg、shrine、text、woman 原始大图，**未伪造替代图，未把空缓存写回仓库**。完整 v4 的像素截图对照尚缺；源码/素材保护证明见 `checks/protected-baselines.json`。
- 手机 P2 使用 v3 已有的手机取景图；它不能冒称为另有一份已认可的“手机 v4”。
- 未接 P4、未写飞书、未改 Figma、未发布。短视频未录制，不用截图拼接冒充真实录屏。

## 文件分工

- `junction.js` 滚动位置、专色映射、星轨与专题逐格切换；`junction.css` 响应式布局。
- `assets/frame-*.svg` 可编辑结构；`assets/frame-geometry.json` 开口与玫瑰窗锚点。
- `assets/water-ink-paper.png` 图像生成素材经浏览器专色映射后导出的生产位图，像素清点只有两色。
- `tools/build_assets.py` 只重建结构骨架和复制只读专题快照，不生成装饰美术、不重建已拒绝的程序排线。
- `PROMPT.md` 记录素材制作方式与提示词。

物理反向滚动与触屏手势未独立完成浏览器验证；本版已检查的是滚动位置驱动代码、24 次按钮循环及两种视口取景。
