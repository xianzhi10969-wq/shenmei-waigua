## 3. Grok 收到新施工授权后的唯一任务

**首先，不是直接做几版！** 必须用真实案例解释“案例来源 + 提炼的色彩作用机制 + P2 的具体应用 + 怎么验证”，内容包括：

1. 背景：为什么采用白、暖白、黑或深墨，而不是从通用 UI 色卡抽取“高级色”。
2. 色彩面积：画面中的“背景/作品/文字/小面积辅助色”分别怎样占据视觉权重；**作品自身颜色不能机械纳入 UI 的 60/30/10 品牌色比例**。
3. 跨页：研究 P1→P2 已验收黑白节奏，不能只看 P2 一张。
4. 色块：作为章节、视觉停顿、信息层级的构成要素；不为装饰添加色签。
5. 容器与作品：不能让背景/楼梯抢走四问和星星叙事中的注意力。

然后在 Figma **复制 539:8** 制作 2–3 个真正有区别的、独立可编辑的配色实验 Frame。每个版本需：
- 不动 TEXT 内容、字体、字号、位置、行距/间距、栅格和阅读顺序；
- 不重绘、不变换、不替换原插画图层，原图锁定；
- 只在有可验证作用时，改变副本的背景最终呈现、文字色、现有线描/插画的明暗色关系、必要的极小功能色；
- 各版有不同的**编辑色彩机制**，而不是只换背景色；
- 提供 Figma 精确 Frame 链接、来源与色彩理由、读者视觉注意力对照、实物渲染截图和风险；
- **全部待审**，用户未选定前停在阶段②，禁止进入字体/其他页面设计。

用户特别强调：禁止只给色号、禁止生成效果图替代可编辑 Figma、禁止普通网页配色模板、禁止早于审批进入下一阶段。

## 4. 上次 ChatGPT 配色为什么失败：请 Grok 以此为反例

三个版本实际是：
- A：暖白背景 + 黑色文字。楼梯在亮底更抢眼；没有可证的刊物级色彩结构。
- B：深墨底 + 暖白文字。与原反相相似，并未实质改善主次。
- C：与 A 类似，只将四个编号变赭红。所谓“章节色签”没有真实导航任务，仅是装饰。

尽管三个 Frame 都真实可编辑、图层哈希与字号坐标核对通过，**用户明确评价难看、认为没有实际使用研究和 GitHub Skill**。三版不能复用，不能宣称在视觉上合格。

失败模式：
- **以案例给随意 HEX 命名，而非分析其配色机制**（“Kinfolk＝米白”“The Gentlewoman＝编号变红”是错误转译）。
- **用工具不等于用方法**：GitHub/Figma 被调用，不代表上游 Grid / Editorial Design Skill 已落实到实际设计逻辑。
- **把技术验收冒充审美验收**：只检查 node tree 和截图存在，未批评三版过度相似、楼梯更抢眼、没有编辑节奏。
- **没有看清 IMAGE + DIFFERENCE** 的颜色混合结构；误把 Frame 背景色当最终纸张色。
- 另有工具发现失误：ChatGPT 曾未检查工具目录就错误宣称 Figma 不可用、让用户切换环境；随后查明工具始终可调用。后续不得以未验证的“无工具/没权限”作为拒绝理由。

**处理原则**：如视觉目标受限于单张栅格插画，必须明确报告这一具体限制并征求用户同意，不许偷偷拆层/重绘、以图像生成绕过 Figma，也不可为凑够三个方案重复换色。
