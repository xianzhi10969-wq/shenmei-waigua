**现在的做法（读代码核实）**
- 页面 `#run` 高 520vh，里面 `#stage` 是 `position:sticky` 钉住的一屏；进度 `p = scrollY / (run高 − 舞台高)`，由 scroll 事件触发 `requestAnimationFrame` 重画。
- 节拍表（进度）：`0–0.05` 静止；`0.05–0.65` 纸升起，曲线 `smoothstep`；`0.65–0.80` 停稳（什么都不动）；`0.80–0.96` 封面擦出，曲线 `cubic-bezier(.22,.61,.36,1)`；`0.96–1` 终态。
- 纸：`translate3d(0, Math.round(H*(1-rise))px, 0)`（取整）。封面和窗下文字：`clip-path: inset(0 0 X% 0)` 硬边。
- 取整后的 Mobile 390×844 下，滚动总长约 3545px：纸升起约 2127px、停稳约 532px、擦出约 567px。

**已知不丝滑的可能原因**
下面分两类：**已核实**是我读代码并算过数；**待核验**是推论，没在真机上验证。

已核实：
1. **封面擦出开始处速度突跳（最可疑）**。擦出用的 `cubic-bezier(.22,.61,.36,1)` 起始斜率约 2.8，我按 Mobile 数了一下：擦出边缘最大速度约 **4.1 px/滚动 px**，而纸升起的最大速度只有约 **0.6 px/滚动 px**。进度到 0.80 的那一帧，擦出速度从 0 直接跳到最大值（约 7 倍于纸的速度），这是速度不连续。
2. **窗下文字擦出开始处也有速度突跳**。窗下文字的 clip 是封面进度 `rv` 在 0.7–1 的线性映射，进度约 0.85 开始时速度从 0 直接跳到约 4.1 px/滚动 px，同样不是缓入。
3. **纸升起/擦出之间是「死区」**。停稳段约 532px 的滚动里画面完全不动（没有缓入缓出，是硬停），手指滑了一大段画面没反应，容易被感觉成「卡住了」「奇怪」。同时纸到顶时 smoothstep 速度归零，一进死区就整个静止。
4. **一条曲线不连续的拼接**：三段用三种不同的函数（smoothstep / cubic-bezier / 线性）分段拼，拐点处速度不连续（上面 1、2 是其中最大的两处）。smoothstep 虽然两端速度为 0，但加速度在 p=0.05、0.65 处有跳变。
5. **纸的位置取整**：`Math.round` 让纸上沿每次只能落在整数像素。纸升起的速度是 0.6 px/滚动 px，慢滑时会出现「一格一格」的台阶感（每步 0 或 1px，不均匀）。这是为了边不糊做的取舍，可以用 transform 亚像素或 DPR 对齐替代（硬边要保持）。
6. **全程逐帧由滚动位置直接驱动，没有任何惯性/缓动**：画面位置 = 滚动位置的纯函数，手指一停画面立刻停，也没有跟手后的缓冲。

待核验（推论，没验证）：
7. **移动端滚动与 JS 重画不同步**：手机浏览器的滚动在合成线程，scroll 事件→rAF→改 transform 在主线程，滑动中常晚一两帧，纸会相对手指有「拖在后面/抖」的感觉。需要在真机或 Chrome 远程调试里录帧确认。
8. **地址栏收放导致高度变化**：`#run` 用 `vh`（大视口），`#stage` 用 `dvh`，`H` 取 `stage.clientHeight`。手机地址栏收起/展开时 H 会变，纸位置和进度分母会一起变，可能出现一次跳动。待核验。
9. **`clip-path` 对大 PNG 的重绘成本**：封面窗是大图，擦出时每帧都在改 clip-path，低端手机可能掉帧；`assets` 共约 18MB，首次解码也可能卡。待核验。
10. **封面擦出结束处**：bezier 末端斜率为 0，结束本身是顺的，但进度 0.96 之后到 1 是静止，目前看没问题；不过「开始」突跳（1）比「结束」明显得多。
