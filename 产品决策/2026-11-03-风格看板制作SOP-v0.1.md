# 审美外挂｜风格看板制作 SOP v0.1

日期：2026-11-03。范围：每个风格词条的真实素材拼贴看板；不含首页重设计、全站导航、动效或部署。
状态：流程提案，尚未经用户逐条确认。依据：用户采用 starter-pack 拼贴形式，并对 Coquette 第二版反馈“好看！”；该反馈肯定本次视觉结果，不扩大为全站上线、所有构图或字体已批准。

## 1. 要交付的东西

每个词条交一张“能认出这个风格、愿意停留细看”的拼贴。画面承担第一层体验，原文解释与来源承担第二层阅读。看板要展示一组有关系的真实细节，不靠一段定义才能成立。

统一制作方法、标题/来源的阅读层级与交付规格；各词条的配色、密度、形状、主图和空间关系按内容决定。Coquette 的椭圆、粉绿、中央裙装不成为全站模板。看板本体与所在产品页面的外壳分开处理，当前白底小样不等于全站改白底。

## 2. 开始前：锁定内容、版本与范围

1. 核对远程 master 的 CURRENT_STATE、PROJECT_CONTROL、AGENTS、README、Editorial Layout Skill 和相关创作记忆；用户最新明确指令优先。
2. 在词条制作单填写：词条 record_id、标题、所属专题、原定义、关联案例、数据读取日期/版本、已有看板版本、本轮要改变的变量。
3. 飞书仅通过已安装的 Lark skill / lark-cli 只读获取。本项目每次调用显式传入 --profile aesthetic-feishu --as user；按当前用户指定账号，不依赖默认 Profile。远程历史中的无 Profile 写法不能覆盖当前明确指令。
4. 主 Base 为 IGctbcuwPaE6hMsmAoicJddpn3U；词条 tbl2gR8WBoqCQyGz；案例 tblpdRYutnm12T0y。不用早期演示 Base 或备份表。
5. 读关联记录并走完分页，逐个下载附件。凭据、临时授权链接留在访问环节，不进入交付网页。前端使用有日期的静态快照，不能称实时连接。
6. 素材状态分别记“已取得、记录无附件、下载失败、来源未明、已取得但未选”。未知不得填成零缺失。

产物：原文快照、原图清单、来源与许可记录、当前任务单。此时还不排成品。

## 3. 先理解：写出这一板究竟让人看见什么

制作人依据真实词条与案例写三项内部编辑判断：
- 最想让人直接看见的一个特征或关系。
- 支撑它的 2–4 个可见线索：具体到轮廓、构造、光线、表面、色彩或空间关系。
- 最容易混淆的邻近风格，以及本板用什么细节避免混淆。

这些是内部判断，不能冒充后台原文。对外标题、定义等沿用真实字段；拟写的新文案另列待审，不偷偷替换。

不要把“同色、好看”当作属于该风格的充分理由。跨服装、家具、艺术、空间选材仅在真实案例支持时进行，不强凑“每类一张”。文化概念与历史风格尤其避免缩成刻板物件清单。

## 4. 选材：先看全部缩略图，再挑一组互相补充的图

先做带文件名/记录号的原图接触表，逐张检查原图。为候选图标注：

| 角色 | 解决的问题 | 取舍依据 |
| --- | --- | --- |
| 视觉主图或主组 | 第一眼停在哪里，整体气氛从哪里来 | 信息够明确、尺寸够用、不会将词条缩成单件商品 |
| 补充案例 | 这种处理还如何出现 | 提供新关系或不同应用，而非重复主图 |
| 细节 | 值得靠近看什么 | 放大后能读出工艺、纹理、形态等信息 |
| 环境 | 细节为何在这里成立 | 空间、光影、人物姿态或背景确实参与风格判断 |

不是四类必须齐全，也不把它们排成四个栏目。初排可从约 5–9 个视觉单元开始；有内容理由再增减。Coquette v2 的 7 张原图形成 10 个单元，是样例，不是数量标准。

同一照片的多次裁切须各自承担不同信息，不能算成多个独立案例。删除一块后若既不损失识别信息，也不损失必要的视觉关系，优先删。

检查能否进入制作：
- 可制作：有清楚的视觉核心，也有能补充或对照它的有效素材。
- 可做精简板：材料少但信息完整，用更少、更大的图，不复制碎片凑满。
- 待补资料：核心特征没有证据、关键图不可辨认，或只有一个案例却要声称代表整个风格。交缺口清单，不能伪造“完成板”。

## 5. 参考研究：每次只解决具体问题

从已积累的参考库选 2–3 张真正相关的拼贴；遇到新问题再补查。必须实际看图，记录作者/来源及未核实项。
每张只回答“借什么”：色彩面积、尺度差、轮廓嵌合、图与细节的关系、留白或密度。不能只写“高级、复古、杂志感”。

参考是方法证据，不自动成为飞书内容或生产素材。外部素材的建议放到补资料清单，交用户决定；当前流程不写入飞书。参考作者未明时如实注明。

## 6. 黑白结构：按素材的性质决定拼法

先做可编辑黑线白底 SVG，用中性占位标记主次、视觉范围和阅读顺序，桌面与手机各一份。新结构按项目既定要求审阅；已明确批准的结构按授权复用，不重复索要同一批准。

可从以下几种组织方法选择或混合，它们是思考起点：
- 轮廓明确的物件：适度去背、大小交错，观察物件之间的空隙。
- 空间/光线主导：保留较完整场景，少量细节围绕它；不要抠掉造成该风格的环境。
- 纹理/工艺主导：全貌和近景配对，避免全板变成无法辨认的纹理块。
- 图形/构造主导：安排可比较的视角、尺度和重复，使共同特点可见。

建立一个明确的首要视觉重心。后续素材形成少量有联系的组，再留下组与组之间的空间。物件可以叠压，但不遮住用来识别风格的部位。
默认不增加统一的椭圆、撕纸边、胶带、花边、阴影；只有它帮助当前画面才用。不要把所有东西都旋转，也不要把全部图裁成相同矩形。

E01 验证：标出预计先看、再看、最后细看的区域，核对实际缩略图是否成立。
E02 验证：记录画布、边距、安全区域与定位；手机独立计算。隐藏栅格是支撑，不把拼贴变成九宫格。
E05 验证：逐项列出重叠处，确认主信息、正文和来源入口没有被盖住。

## 7. 配色：从真实图像建立关系

结构认可后再集中处理颜色。先把已选原图一起看，判断大块颜色、明暗与饱和度的分布，然后通过选图、裁切范围、面积与位置调整。

- 找出大面积颜色、较小的呼应色，以及深浅之间的支撑。约 3–5 个代表色可作观察记录，不是强制色数。
- 丰富感可来自同色的不同明度、冷暖、透明度和表面；单色风格不必人为增色。
- 检查一个颜色是否只孤零零出现。能用其他真实细节呼应时再安排，不加无关图片凑色。
- 色彩比例没有统一的 60/30/10 配方；白底面积也参与判断。
- 不给原图统一滤镜、染色，不把材质色改成品牌色。页面辅助文字色另检查可读性。
- 色板是制作检查工具，不要求每个看板都展示一排色块。

Coquette 的具体教训：抠掉《秋千》绿荫后，画面失去大块深色；浅色衣料重复也削弱层次。v2 通过保留环境、调整主图面积和增加粉色反光改善关系。这说明应先检查被裁掉的信息，而不是先加装饰。

字体独立于配色。沿用已认可的文字角色；只有确有新字体任务时才依项目“结构→色彩→字体”阶段推进，不每个词条重新选一套字体。

## 8. 裁切与去背：以可辨认为准

只用非生成裁切、透明蒙版和排版；原图保持不变，派生图另存。
- 环境贡献颜色、空间或语义时，保留环境。
- 毛发、蕾丝、薄纱、反光、烟雾等难以准确分离时，优先保留照片背景或局部照片，不硬抠。
- 裁切不能歪曲作品、制造原照片不存在的物件关系，不能去掉水印或必要署名。
- 小细节必须在最终手机尺寸可辨认。若像一块不知所云的碎片，改成更完整的局部、放大或撤下。
- 逐件保存原图来源、裁切坐标/蒙版、用途、输出尺寸和修改说明；同一源图的不同裁片可追溯。

Coquette 的银花单独去背后过碎；保留银花与手套一起出现，辨认更清楚。这是“少抠一点更好”的实例。

## 9. 桌面与手机：保留同一内容逻辑，重新安排空间

桌面处理整体观看与多处细看；390px 手机处理纵向先后、可辨认尺寸和连续色彩。
手机不把桌面整张缩小，也不机械把所有物件排成等宽卡片。必要时合并重复裁片或减少次要单元，说明差异，核心证据不能悄悄丢失。

首屏能看见标题和有意义的主视觉；页面高度随内容决定，不设全站同一长图高度。兼查邻近窄屏，防止只有 390px 恰好正常。

标题、原文和来源保持可编辑。完整出处放到画面外；画内编号轻量但能操作，点击区域适合触控，有可见键盘焦点和描述，不把小号数字本身当作完整触控区。对外说明不要塞满内部制作信息。

## 10. 两轮验收：先看画，再查事实与交付

视觉自检：
1. 缩成缩略图：主次和色块是否清楚，是否成团或失衡？
2. 隐去标题看图：能否说明这个风格的特征？这只是内部检查，不宣称真实用户测试通过。
3. 恢复标题读原文：图像是否与词条一致，是否只展示其中一小支却冒充全部？
4. 在实际手机尺寸细看：关键细节、边缘、字号、编号是否可辨认？
5. 与同批其他风格并排：彼此有没有区别，同时仍像同一产品？
6. 与上一版并排：本轮具体改进是否可见，而非只增加了素材数量？

事实与技术检查：
- 原文与记录、图片与关联案例对应；每张可追溯，缺图状态明确。
- 下载成功与版权可公开使用分开记录；许可未核定可本地审阅，不标成可上线。
- 裁切不误导，原文件散列未变，旧版可打开。
- 桌面和手机所有图加载成功；没有横向溢出、文字遮挡或坏链接；来源可打开。
- HTML/CSS/SVG 可编辑；截图只是预览，不能替代源文件。
- 明确本地浏览器检查与真机检查的区别。交互与正式产品衔接未做时单独列明。

判定：事实错误、来源丢失、关键内容看不清、侵入受保护版本，应先修复再交付。视觉偏好交用户评审，技术通过不能替代审美通过。
记录用户原话与对应版本，区分“视觉反馈正向、明确采用、允许替换、允许发布”；不要扩大授权范围。

## 11. 每条固定交付与维护

独立目录：词条稳定 ID / 日期-版本。目录名不只依赖可能变更的展示标题。
至少含：
- index.html、390px 手机预览、双端 PNG；
- editable SVG 结构与可编辑排版源；
- 原图、派生图、素材清单和处理配方；
- 制作单、缺口/未选素材及原因、来源许可表；
- 验证记录、与上一版对照、用户反馈与状态；
- 可离线打开的文件包和清晰入口。

生产复用优先把素材映射、双端坐标、文本、来源与模板分开保存。Coquette 现有内嵌 HTML 是便于离线审阅的样例，不直接充当全站百条风格的生产架构。此次 SOP 不代表已有批量渲染系统。

未来更新：比较 record_id、附件与字段变化，只更新受影响看板，另存版本；有视觉变化重新评审。飞书、Figma 与正式站点是否回写/发布按具体授权执行，不能因看板获得好评就自动上线。

## 12. 全量制作怎么推进

先只读盘点当前真实词条清单，核对分页与实际数量，不把旧文档中的记录数当作本轮总量。给每条标记“可制作 / 可精简 / 待补资料”，另记许可状态，两个维度不混用。

Coquette 之外，建议再选 3 个材料性质不同、数据相对完整的词条验证：空间光线主导、材质工艺主导、图形构造主导。这里只定义选样方法，不预先断言哪些词条已具备素材。

这几条验证后再分小批制作。建议每批 3–5 条作为初始节奏，根据实测耗时调整，不承诺所有词条同样快。每批做一次并排检查，防止每条单看好看、放在一起却都像 Coquette。

可复用：数据读取、原图存档、接触表、来源映射、预览输出与完整性检查。
逐条判断：核心特征、选图、裁切、主次、颜色关系与审美验收。
有新材料类型或持续失败时，修订 SOP 并保留版本，不不断往旧流程追加互相冲突的要求。
