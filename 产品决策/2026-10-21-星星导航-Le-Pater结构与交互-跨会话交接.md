**徽章定义（补充，供画图前对照）**：徽章是一枚**完整闭合的小章**——主体图案与外轮廓长在一起、彼此咬合，整体读作一个紧凑标记；**不是一幅小插画外面再套一个框，也不是图标加花边**。五枚统一外轮廓尺度、线感与墨量，内部符号各不相同，不必每枚都有星星。画法遵循 `视觉研究/AIGC风格提示词/` v7 绘图语言。结构参考：Koloman Moser《Ver Sacrum》圆形装饰小章（约 1898）、George Auriol 印记／组合字、穆夏圆章。一次只画一枚，对照参考与本定义验收后再画下一枚。

## 0. 30 秒接续摘要｜先读这一节

- **这是全站导航，不是 P3 专题柜／P4 书册内部目录，更不是顶部五栏目横排菜单。** 用户希望点击贯穿首页的那颗星星，唤起通往全站主要功能的索引。
- **已认可的是构图骨架**：参考 **Alphonse Mucha《Le Pater》（1899）扉页** 的版式组织——页面左侧约 **1/5** 为竖向、同一尺寸与视觉权重的 **5 枚徽章式导航入口**；右侧约 **4/5** 是**所选功能本身的页面预览**（~~原写：完整的大面积主视觉~~，见更正 #2）；一条较长的**栏目标题带作为独立前景图层直接叠压在右侧图像之上**，不能把它挪成独立页眉／外置 banner。
- **五个入口等权**：不采用「一个主入口、两个次入口、两个辅助入口」的信息层级，也不为左右对称硬凑第六个「敬请期待」。**左侧高度规整、右侧插画自由不对称、标题带穿过主体**，构成 Le Pater 式秩序与不对称张力。
- **预期交互（需求方向，不等于已实现或已验收）**：点击星星进入独立索引空间；用户选择不同徽章，右侧切换为**对应功能的页面**，叠压标题带同步变更；用户再明确操作才进入栏目；关闭则返回原阅读位置。
- **五个目的地（当前产品 IA）**：「寻找感觉」（独立检索）、「美学专题／浏览专题」、「好奇心漫游」、「意象实验室」、「艺术资源」。这些是五个功能入口，不能与 P1–P6 滚动场景一一硬绑定。

## 1. 产生背景｜为什么要用星星而不是常规导航

项目首页是连续滚动的艺术世界，不希望在 P1 顶部添加「寻找感觉｜浏览专题｜好奇心｜意象实验室｜艺术资源」的普通导航条，也不希望多发明一套脱离原线描世界的 UI。用户提出让 **P1 神龛／祭坛里的星星**从 P1 落向 P2 水面、之后随滚动继续贯穿 P3/P4 与后续场景；向上滚动应可逆。星星是统一视觉母题、跨屏转场线索，也可以成为全站索引的触发入口。

- **已完成独立代码基线**：P1→P2 的星 B v4：[README](../web-prototypes/p1-p2-reveal-star-v4-2026-10-21/README.md)、[动效说明](../web-prototypes/p1-p2-reveal-star-v4-2026-10-21/MOTION-NOTES.md)（八角星 B，墨色/米色，滚动下落，水面交接与反向滚动）。这不代表 P1–P6 全部连通。
- **P2→P3 叙事衔接（设计意向）**：P3 **上方**承接 P2 的水面，星星继续进入 P3 的柜体／展示结构某个合理位置；P3 下方不必一直是水。具体落点、P3 对接的动效与工程验证仍需另行验收。
- 星星究竟落在 P1/P2 的哪个坐标、位于导航界面开关的哪个位置、是否需要文字提示和备用入口，**不因本文件被提前锁定**。尤其用户曾明确要求暂不指定「右侧」。

## 2. 核心原作参考｜真正借的是什么

- **Alphonse Mucha, Le Pater（1899），扉页**。原作图源：[Galerie Fledermaus · Le Pater Title Page](https://www.galeriefledermaus.com/artworks/categories/12/9957-alphonse-mucha-le-pater-title-page-1899/)；[Mucha Foundation Le Pater](https://www.muchafoundation.org/en/gallery/themes/theme/le-pater/object/295)。
- 用户亲自指出的版式：**左侧很窄的竖列**，其中连续排列**大小一致的徽章**（原作不等于恰好五个）；右侧是**占约 4/5 的整体插画主体**；大标题长带**横贯并覆盖在右侧主体画面上**，而不是独立脱离图像。辅助文字也可参与版面。
- 不要把它误读成「主次不同的五个卡片」，也不要改成「中心星星往周围平均放射五个按钮」。**借结构/图文关系，不复制原作人物、宗教符号、纹饰、文字字体或轮廓。**
- 另有项目已有参考：[产品参考库](../参考库/产品参考库/README.md)、[2026-10-21 画风与收藏空间（含穆夏作品）](../参考库/产品参考库/2026-10-21-P3-P4-画风与收藏空间/README.md)。参考画风 ≠ 用户认可的美术方案。

## 3. 功能与布局约束

### Web（布局已被认可，仍可在验收中局部调整）
- 画面整体作为一幅艺术索引，**不是 PPT 左文右图，也不是普通左侧 sidebar + 右侧卡片**。
- 左侧约 **18–22%**（约 1/5）作为五枚**等尺寸、等权重**徽章的固定竖列；外部布局整齐，**每枚内部将来应是独立原创、可区分、同画风的图案**。**尚无一枚徽章的美术形态因此获得批准**。
- 右侧约 **78–82%**（约 4/5）保留一块**不切分成多卡片**的整体主视觉区域；具体五幅预览内容、比例、安全区与画法尚待素材实验。
- 一条**长标题带在右图之上的图层**横穿图像；选中栏目时联动标题、图像和辅助说明。标题带最终颜色、字形、位置细节、透明度等**未获批准**。
- 左列重复建立秩序，右图自由不对称；**不能为了五个奇数入口而做 3+3 网格，不能加装饰框凑整齐**。

### Mobile（需要单独构图与验收）
- **核心信息层级仍保留五徽章入口 + 大面积预览 + 叠压标题带**；不能只是把 Web 截图缩小。
- Figma 有 **390×844** 移动端视口试排（外层另含备注区），其中**窄左列**仅是结构探索，不代表用户同意徽章大小、密度、触控位置、文字可读性及最终视觉。
- Web 可研究 hover 预览，手机不依赖 hover，需设计 tap 切换与明确的「进入」动作。触控可达性、长屏尺寸与操作舒适度要实机验收。

### 交互状态（待制作并验证）
1. **CLOSED**：维持原 P1–P6 场景与可互动星星；不额外加现代横排导航。
2. **OPENING**：点星星，响应并**揭开世界背面／打开隐藏索引**；这是用户认可的创意方向，具体揭幕视觉和动画曲线**未定稿**，不得宣称已经有成品。
3. **INDEX DEFAULT**：五枚等权徽章及一幅默认栏目预览。默认展示「寻找感觉」属于实验画板选项，**不代表最终指定**。
4. **SWITCH**：选择某徽章，保持左列结构不变，右图与长标题带切换；不弹出五张卡片、不改变每枚徽章的基本尺寸。
5. **ENTER**：点击/触碰明确入口，前往对应独立功能页。不要把 hover 自动当跳转。
6. **CLOSE / RETURN**：可以关闭索引，恢复原场景与滚动进度；上滑星星运动应与下滑可逆。
7. **可发现性与减弱动效**：研究能否识别星星是可点击入口、键盘/触控、可关闭、系统减少动态效果；尚待实现。

**工程说明**：v4 中下落星与 P2 原位星通过交接状态达到视觉连续；将来应共享逻辑状态而非给每一颗图像另写一个独立导航。此项为建议，不等于代码已集成。

## 5. 已排除的方向

- 普通顶部横排五栏目、无缘由的胶囊/汉堡式菜单；导航入口的位置**仍未定**。
- 点击中心星星后五个按钮按半径均匀发散的普通 radial menu、五张独立等分卡片、3×2 六宫格、平行排列五张装饰牌匾；这些缺少原作图文组织的张力。
- 以「一个主入口两次入口两辅入口」制造人为不平等：用户明确反驳，**左侧五枚视觉权重必须相同**。
- 为凑偶数新增一个「敬请期待」栏目：用户曾提为备选，但最终选择五枚等权徽章结构，**没有确立第六个入口**。
- 为了方便代码实现而使用 CSS 伪钢笔线画正式美术／使用过密 3D 特效或仿照参考原作的宗教物件。

## 6. 下一轮聚焦执行｜分阶段、逐项验收

**A. 已完成的结构验证**：Web+Mobile 的骨架在 Figma 建立；**只有布局比例与图层关系通过概念确认**，不能升级称「索引页最终视觉定稿」。

**B. 仍须交付并验收**：
1. **徽章艺术设计**：检索并记录真实徽章／版画／装饰艺术实例，定义统一外轮廓约束与五个可区别的内部符号；**逐枚制作、逐枚验收**，不要每枚都重复星星，五徽章当前一个都不能按 Figma 占位图当成通过。
2. ~~右侧五幅大型预览独立绘制~~（已作废，见更正 #2）→ **右侧呈现五个功能各自的真实页面**：确定每个功能页在 4/5 区域内的预览/嵌入方式、与标题带叠压的安全区，不另画插画。
3. **标题条与排印**：专门研究适配 Le Pater 式插画的文字条与字体，而不是沿用 Figma 临时黑条；五个实际栏目名字都要测试长度和层级。
4. **打开／关闭交互**：星星作为触发器如何揭开独立索引，如何逆向关闭恢复阅读位置；Web 和 Mobile 交互分镜、动效演示与减少动态效果均待实测。
5. **联动切换**：徽章选中反馈、右图及标题同步切换、进入目标页，实际跑通后验收，Figma 静态双状态**不是交互代码已经完成**。

每轮必须遵循 **「研究 → 收束决议（已定/淘汰/待验证） → 拆可执行任务 → 独立版本制作 → 按具体标准验收 → 更新 GitHub」**。任务可按合乎逻辑的批次执行，但不要新一轮研究就重画整页，也不要拿未经批准的美术素材覆盖已通过基线。**没有实物、动效、确认反馈就写「待验证」，绝不伪报通过。**
